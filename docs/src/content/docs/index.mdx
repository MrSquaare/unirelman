## What unirelman does

You describe your changes in small files called changesets. unirelman turns them into the next version of each package, writes the changelog, commits the release, then publishes it: npm packages, Git tags, and GitHub releases.

<CardGrid>
  <Card title="Plugin-based" icon="puzzle">
    Every step is a plugin: where versions live (npm), how they bump (SemVer, CalVer), where changes
    come from (Changesets), what gets published (npm, Git, GitHub).
  </Card>
  <Card title="Monorepos and single packages" icon="seti:folder">
    Each scope is versioned on its own, with its own versioning scheme, or together with others.
  </Card>
  <Card title="Prereleases" icon="rocket">
    Move a scope through alpha, beta, and release candidate channels, then back to stable.
  </Card>
  <Card title="GitHub Action" icon="github">
    A release pull request that stays up to date, and publishing when you merge it.
  </Card>
</CardGrid>
